## 二、规律推断

### 改写策略（核心：彻底重写，不是同义词替换）

1. **整句重组**：保留信息核心，重新组织表达
   - 原文 "运动也不会流白汤" → "暴汗也不怕花成地图"（流→暴汗、白汤→地图）
2. **加比喻 / 夸张**：
   - "天生好皮"、"花成地图"、"狂飙"、"白印子"、"撑场面"、"整这个"
3. **改换主语称呼**：兄弟 / 哥们儿 / 你 / 帅哥 / 有品的兄弟
4. **改换动词**：试试 → 冲它 → 来一发 试试
5. **加感叹 / 反问**：
   - "绝了！" "够自然吧？"
6. **加语气助词**：贼、特、超、确实
7. **加场景细节**：
   - "暴汗" "围巾大衣随便裹" "妆感贼自然"
8. **每个版本风格不同**：v1 重感叹、v2 重对比、v3 重场景

### 风格特征

- **网感重**：抖音流行用语
- **口语化**：瞅瞅 / 瞧瞧 / 哥们儿 / 整这个 / 来一发
- **短句多**：每个版本 1-3 个短句而非长句
- **保留人称转换**：原文是描述（无人称）→ 改写带"你/兄弟/哥们儿"

### 短词处理

原文 "抖音"（2 字）→ autocut 仍生成 3 个变体而非保留：
- 抖音见 / 在抖音 / 抖音上

含义：**短词也补全成完整短句**，不能直接复制。

### 长度控制

- 原文 "看看看看，遮瑕效果还不错吧，自然遮瑕它也不假白，妆效也很自然"（27 字）→ 改写均 20-26 字
- 原文 "抖音"（2 字）→ 改写 2-4 字（贴近原文长度）
- 原文 "想变帅兄弟你真的可以去试试它"（14 字）→ 改写 8-14 字

→ **长度大致与原文匹配，±50% 内**

### name 提示作用

`name`（如"遮瑕效果展示"）作为**风格 / 视角提示**喂给 LLM，使改写不偏离镜头主题。
观察："遮瑕效果展示" → 3 版都围绕"遮瑕"展开；"行动号召" → 3 版都是号召动作。

## 三、反推 Prompt

### System Prompt

```
你是短视频口播文案改写大师，专做爆款风格的语义改写。
擅长把平淡描述变成抖音网感强、口语化、有梗的版本，让每条文案都像主播亲口在说。
```

### User Prompt 模板

```
请把以下分镜文案改写成 {N} 个完全不同表达的版本。

【核心要求】
1. **语义不变**：传达的核心信息和卖点必须一致
2. **彻底重写**：不是换近义词，要重新组织表达：
   - 改换主语 / 称呼（你 / 兄弟 / 哥们儿 / 宝子 / 帅哥）
   - 改换动词（试试 → 冲它 → 来一发 / 看看 → 瞅瞅 → 瞧瞧）
   - 加比喻 / 夸张（流汗 → 花成地图 / 自然 → 跟天生好皮似的）
   - 加感叹 / 反问 / 语气词（绝了！/ 够自然吧？/ 贼 / 特 / 超）
   - 改换句式（陈述 → 反问 → 感叹）
3. **网感口语化**：用抖音流行用语，避免书面语
4. **每版风格不同**：v1 / v2 / v3 各自有不同侧重，避免雷同
5. **长度控制**：每版字数与原文相近，±50% 内
6. **短词补全**：原文很短（≤4 字）时，可补全成短句而非直接复制
   例：原文"抖音" → "抖音见 / 在抖音 / 抖音上"

【输入】
分镜名：{NAME}（仅作参考，告诉你这条说什么）
原文：{CONTENT}

【输出】严格 JSON（禁止 markdown code block 包裹）：
{"versions":["...","...","..."]}

versions 数组长度必须等于 {N}。
```

### 风格变体（按 RewriteOptions.style 切换）

- `default` / `colloquial` → 上述 prompt 原版
- `kol` → 在 system 加 "用 KOL 种草口吻（宝子们 / 集美们 / 敲重点 / 真的会回购 等）"
- `live-commerce` → 在 system 加 "用电商直播话术（家人们 / 上车 / 这个价 / 拍三送二 / 卖完不补 等）"

## 四、对比当前 mock 实现

| 维度 | mock | autocut |
|------|------|---------|
| 改写深度 | 同义词替换（非常→超级） | 整句重组 |
| 修辞 | 前后缀拼接（"说真的，..."） | 比喻、夸张、感叹 |
| 主语转换 | 无 | 你 / 兄弟 / 哥们儿 |
| 短词处理 | 直接复制 | 补全成短句 |
| 风格区分 | 3 版规则化（idx % 3） | 3 版各有侧重 |

→ 完全升级到真 LLM + 上述 prompt 后差距可显著缩小。

## 五、降级策略

```
LLM 调用
  │
  ├─ 成功 + JSON 合法 + len == N → 直接用
  ├─ 成功但 versions 数量不对 → 截断或用原文补齐
  ├─ JSON 解析失败 → 按行切分文本作为 versions
  └─ LLM 失败 → 回退到 MockLlmAdapter 规则变形
```

## 六、调用接口

`LlmAdapter.rewrite(original, count, options)` — 已存在，仅需更新 prompt 实现。

```java
List<String> versions = llm.rewrite(shot.content, count, RewriteOptions.builder()
    .style("default")  // 或 "kol" / "live-commerce"
    .temperature(0.85) // 高温度增加 3 版差异
    .maxTokens(500)
    .build());
```

调用方 (`CmScriptFissionService.fission()`) 已就位，无需改动。

## 七、温度建议

- 默认 `0.85`：保证 3 版风格各异
- 风格固定（kol / live-commerce）：`0.75`
- 严格保留原文：`0.5`（不推荐，效果接近 mock）
