## 零、完整执行流程（用户实测顺序）

> 来自团队实测的端到端使用顺序。Cutmatrix Agent 编排链路按此顺序对齐。

```
┌─ Step 1 ─ 提取视频及文案 ────────────────────┐
│   输入：top 视频链接                          │
│   输出：无水印视频文件 + 转写后的口播文案     │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 2 ─ 文案裂变 ──────────────────────────┐
│   3 种模式可选：                              │
│   ① 整片文案改写                              │
│   ② 分镜级文案改写                            │
│   ③ 多个空分镜（仅占位，后续填）              │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 3 ─ 语音合成 ──────────────────────────┐
│   导入裂变后文案 + 选音色/语速 → 批量配音     │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 4 ─ 拆片（按内容形态三选一） ──────────┐
│   4a. 按场景拆解视频（普通短视频）            │
│       导入素材 + 目标章节结构 → 自动+手动     │
│   4b. 按语义拆解视频（直播切片）              │
│       分析口播 → 按语义边界拆解 → 主题归类    │
│   4c. 拆解电商直播话术循环（电商直播）        │
│       识别商品 + 话术循环 → 勾选导出          │
│       通常作为 5/6 的前置                     │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 5 ─ 提取章节结构 ──────────────────────┐
│   导入音视频 → 转写口播 → 输出章节文件夹树    │
│   先做大的框架拆分                            │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 6 ─ 按语义拆解视频 ────────────────────┐
│   分析口播 → 按语义拆 → 自动归到目标主题      │
└──────────────────────┬───────────────────────┘
                       ↓
┌─ Step 7 ─ 编排（二选一） ────────────────────┐
│   7a. 诸葛亮模式                              │
│       按章节高质量混剪 + 有声/无声素材均可    │
│       各章节随机配音                          │
│       多种音画同步模式                        │
│       全局随机选取 BGM                        │
│   7b. 孙悟空模式                              │
│       整段配音高质量混剪                      │
│       根据配音文案和时长，从各章节提取素材组合│
│       多种音画同步模式                        │
│       适用：直播集锦、电商短视频、信息流      │
└──────────────────────────────────────────────┘
```

### 拆片路径选择决策树（Step 4）

| 内容形态 | 推荐路径 | 备注 |
|---|---|---|
| 普通短视频（结构清晰） | **4a 按场景拆解** | 最常用 |
| 直播切片（口播为主） | **4b 按语义拆解** | 跳过 4a |
| 电商直播录像 | **4c → 5 → 6** | 4c 先选商品段，再章节化 |

### Steps 5-6 的关系

- Step 5（提取章节结构）= **粗结构** —— 把音视频划成顶层章节文件夹
- Step 6（按语义拆解）= **细分主题** —— 在章节内按语义归类到子主题
- 一般是先 5 后 6；若内容已经是章节化好的，可跳过 5 直接 6。

### Step 7 模式选择

| 决策因素 | 诸葛亮 | 孙悟空 |
|---|---|---|
| 配音颗粒度 | 各章节独立配音（随机分配） | 整段一份配音 |
| 适合场景 | 多卖点拼接、抗查重 | 整段叙事、单一主题 |
| 典型用途 | 种草内容、品牌矩阵 | 直播集锦、电商短视频、信息流 |

## 一、核心哲学

### 1.1 中视频原创审核的本质

平台对原创性的审核存在**权重排序**：
```
视频画面 > 文案 > 音频 > 音效
```

含义：只要每条成片的画面组合 + 文案 + 配音是独一无二的组合，即可通过原创审核。这是矩阵化批量生产的合法性基础。

**禁忌**：
- 直接搬运他人视频
- 仅做简单加工（裁剪、变速、调色）
- 同账号重复发同质化内容
- 整段配音的剪辑成片不得超过 5 条（蹭碟片 + 跟拍音频除外）

### 1.2 原创性的三类拆解维度

| 维度 | 拆解方式 | 独立性来源 |
|---|---|---|
| **视频素材** | 长视频 → 独立场景镜头池 | 不同组合排列 = 独一无二画面 |
| **配音文案** | 同一卖点 → N 个语义近似变体 | 不同表达 = 不同口播 |
| **音频/BGM** | 替换 BGM、加音效 | 听感差异化 |

三个维度的笛卡尔积构成"几千亿种组合"。算法负责从中筛除重复、产出无重复的独立组合。

### 1.3 受控组合 vs 全随机组合

| | 全随机（autocut 默认） | **受控**（玛丽黛佳特化） |
|---|---|---|
| 组合逻辑 | 全排列去重 | 按卖点框架（动机×手法）匹配 |
| 适合 | 矩阵号走量、信息流灌注 | 品牌内容、卖点叙事 |
| 质量 | 过原创审核即可 | 必须过品牌调性审核 |

Cutmatrix 默认采用**受控组合**：每个段落标签（HOOK / SCENE / BENEFIT / PROOF_CTA）只从对应标签的镜头池中召回。

## 二、素材数量与产能的数学关系

### 2.1 千条原创标准

```
章节数 ≥ 20            （原创实拍章节 ≥ 15）
每章节独立素材：
  原创实拍 ≥ 20 个
  网络拆片镜头 ≥ 50 个
```

### 2.2 百条原创标准

```
章节数 ≥ 20
每章节独立素材：
  原创实拍 ≥ 10 个
  网络拆片镜头 ≥ 10 个
```

### 2.3 通用公式

```
可生成无重复成片数 ≈ ∏(每章节素材数) × ∏(每章节配音变体数)
```

例：20 章节 × 每章节 50 镜头 + 文案裂变率 N → 可支撑数千条无重复成片。

实战警告：账号一旦爆单，素材池不足或被举报下架就是直接的金钱损失。素材准备是矩阵号的必修课。

## 三、两种核心剪辑模式

### 3.1 孙悟空模式 — 整段配音驱动

**思想**：以完整配音（或 BGM）为骨架，从分镜池随机抽取镜头填充至音频时长。强调叙事连贯。

**文件夹结构（二级）**：
```
品名/                       一级文件夹 = 品名
├── 01_章节A/               二级 = 分镜/章节
│   ├── 001.mp4
│   ├── 002.mp4
│   └── t=003.mp4           t= 前缀 = 不做镜像处理
├── 02_章节B/
├── 配音/                   同层级
│   └── voice_*.mp3
└── BGM/                    必须大写
    └── bgm.mp3
```

**适用**：一段完整解说 + 画面跟着走、品牌叙事段、信息流。

**算法约束**：
- 镜头累计时长 ≥ 配音时长（宁可画面溢出截断，不能配音溢出）
- 整段配音成片 ≤ 5 条/源（避免文案重复被判搬运）
- 时长自动跟随配音

### 3.2 诸葛亮模式 — 章节独立配音

**思想**：每个章节独立画面 + 独立配音。颗粒度更细，画面 × 配音双重变量，更抗平台查重。

**文件夹结构（三级）**：
```
品名/
├── 01_章节A/
│   ├── 001_子章节a/
│   │   ├── 视频素材/
│   │   ├── 配音/
│   │   └── BGM/
│   └── 002_子章节b/
├── 02_章节B/
└── BGM/
```

**适用**：多段卖点拼接、电商带货、长种草内容。

**关键能力**：诸葛亮可针对每个章节/分镜独立选择音频策略（详见第四节）。

### 3.3 两种模式选型决策

| 决策因素 | 孙悟空 | 诸葛亮 |
|---|---|---|
| 内容类型 | 一段完整叙事 | 多段拼接（卖点逐段） |
| 配音颗粒度 | 整段一份配音 | 每章节独立配音 |
| 抗查重 | 中（仅画面变量） | 高（画面 × 配音） |
| 配置复杂度 | 二级目录 | 三级目录 |
| 单条产出量上限 | ≤ 5 条/配音源 | 视章节数指数级 |
| **Cutmatrix 推荐** | 信息流灌注场景 | 默认（搭配段落对齐使用） |

## 四、章节级音频策略（5 模式）

每个章节可独立选择音频处理方式。诸葛亮模式下尤其灵活：

| 模式 | 含义 | 美妆典型场景 |
|---|---|---|
| **一个配音多个视频** | 一段配音覆盖该章节多个画面 | 品牌解说段（卖点阐述） |
| **为配音填充画面** | 按配音时长自动填够画面 | 功效说明段 |
| **为配音循环情节** | 画面循环播放匹配配音时长 | 产品展示 / 质地特写 |
| **无配音 固定素材数** | 保留原声，不加配音 | 达人演示段（真实感） |
| **无配音 至少 X 秒** | 保留原声，控制最短时长 | 达人口播 / 使用体验段 |

每章节还可独立控制：
- 是否去除原音
- 视频比配音长时如何裁剪（剪头 / 剪尾 / 头尾各剪一半）
- 配音是否允许重复使用
- 视频重复率滑块（质量模式 ↔ 数量模式）

## 五、素材准备与拆片

### 5.1 场景拆片（按画面边界）

**对象**：网络长视频、达人原片。

**注意事项**：
- 优先处理好配音，**镜头时长按配音时长区间分配**
- 镜头时长不要短于配音过多；若大量镜头都短于配音，应建立分镜子章节
- 检查每个片段的开头帧和结尾帧，避免转场卡帧夹帧
- 同一镜头不要被多个章节挂载（避免素材复用)

### 5.2 语义拆片（按口播语义边界）

**对象**：直播切片、口播视频。

**关键步骤**：
1. 先做分镜结构拆解
2. 自动分配后**必须人工复核**
3. 不合事宜的镜头直接舍弃
4. 不要选同质化镜头过多的素材

### 5.3 拆片产出 → 章节归类

拆出来的镜头需打标签后归到对应章节：
- HOOK / 钩子 → 01_钩子
- SCENE / 场景痛点 → 02_场景痛点
- BENEFIT / 方案卖点 → 03_方案卖点
- PROOF_CTA / 证明收束 → 04_证明收束
- 未识别 → 99_待分类（人工复核兜底）

## 六、文案 & 配音生产

### 6.1 文案裂变流程

```
原始文案
  ↓ 拆解分镜
得到 N 个分镜（每个分镜 = 一个卖点段落）
  ↓ 每分镜批量改写
每分镜产出 K 个语义近似变体
```

**约束**：
- 每批裂变 ≤ 5000 字
- 单次裂变次数 ≤ 10 次
- 文案需求量大时，用初始文案多次裂变（不是一次裂变 100 次）

**输出格式建议**（YAML 结构化，便于 Agent 消费）：
```yaml
- name: 钩子段
  content: 原始口播
  variants:
    - text: 变体1
    - text: 变体2
    - text: 变体3
```

### 6.2 配音合成

**对话式配音**：文案裂变后保存 JSON 文件，每次只配对应章节的音色。

**链接抓取**：提取视频及文案功能支持多条链接同时处理（换行分隔）。

## 七、极速过滤（无效片段剔除）

三种过滤模式：

| 模式 | 用途 |
|---|---|
| **音频过滤** | 检测纯静音段 → 剔除 |
| **有声素材过滤** | 检测有原声的素材中的低能量片段 |
| **无声素材过滤** | 检测画面无内容的低信息片段 |

**实现底层**：autocut 用 BBC 开源 `audiowaveform` + ffmpeg `silencedetect`。

**Cutmatrix 落地**：作为 `cm-tool-silence-filter` 原子工具，在素材入库前批量过一遍。

## 八、字幕处理

### 8.1 擦除字幕

- 云端处理（消耗资源）
- 必须先**统一画幅**再擦除（先 `转换比例` 工具）
- 拆片后再擦除可省积分（小素材成本低）
- 对跳动字幕，框选区域必须覆盖到字幕跳动到最高的位置

### 8.2 生成字幕

- 批量为视频生成 + 导出 VTT/SRT
- 主流剪辑软件可直接导入
- 每句可手动修订

## 九、音画同步方案（重点）

三个精度级别：

| 精度 | 做法 | 适合场景 | Cutmatrix 采纳 |
|---|---|---|---|
| **粗对齐** | 配音总时长 → 随机填充镜头至时长够 | 矩阵走量、不 care 叙事 | autocut 默认 |
| **段落对齐** | 配音按段落切分 → 每段匹配标签镜头 | **品牌内容、卖点叙事** | ✅ **Cutmatrix 默认** |
| **句级对齐** | 每句配音 → 匹配语义最近画面 | 精品内容、成本最高 | P3 按需 |

### 段落对齐算法（cm-paragraph-aligner Agent 核心）

```
input:
  blueprint_section[] = [{stageCode, narrationDurationSec, narrationUrl, requiredTags[]}]
  segment_pool        = 标签筛选过的 cm_video_segment 集合

algo:
  for each section in blueprint_section:
    candidates = segment_pool.filter(stageCode == section.stageCode AND tags ⊆ section.requiredTags)
    chosen     = []
    accumulated = 0
    while accumulated < section.narrationDurationSec:
      seg = candidates.pop_random_unused()
      chosen.append(seg)
      accumulated += seg.durationSec
    if accumulated > section.narrationDurationSec:
      # 尾部截断
      chosen[-1].endSec = chosen[-1].startSec + (section.narrationDurationSec - sum(prev_durations))
    yield SegmentPlan(section, chosen)
```

**优势**：
- 保证叙事逻辑（痛点配痛点画面，亮点配亮点画面）
- 复用"时长填充"策略解决音画同步，不需要逐帧对齐
- 与现有卖点框架（动机 × 手法）天然对接

### 10.3 Agent 决策规则速查（用于 prompt 上下文）

构建 Agent 时可注入以下规则：

```
RULE-1 原创审核优先级：视频画面 > 文案 > 音频 > 音效
RULE-2 整段配音剪辑成片 ≤ 5 条/源
RULE-3 千条原创：≥ 20 章节，每章节 ≥ 50 网络拆片镜头 OR ≥ 20 原创实拍
RULE-4 段落对齐：镜头累计时长必须 ≥ 配音时长，多余部分尾部截断
RULE-5 文件命名：t= 前缀 = 禁止镜像处理
RULE-6 拆片：检查首尾帧避免卡帧，镜头时长不短于配音过多
RULE-7 章节归类：按 stage_code (HOOK/SCENE/BENEFIT/PROOF_CTA) 自动归
RULE-8 文案裂变：单批 ≤ 5000 字，单批裂变次数 ≤ 10
RULE-9 字幕擦除：必须先统一画幅，跳动字幕框选最高点
RULE-10 同一镜头不允许跨章节挂载（保持目录树心智简洁）
```

## 十一、与现有平台 Agent A/B/C 的关系

**完全隔离**。现有 Agent A/B/C 服务于品牌内容三 Agent 链路（玛丽黛佳种草），Cutmatrix 服务于矩阵化批量生产。两套体系：
- 命名空间隔离（cm-*）
- DB 表前缀隔离（cm_*）
- API 前缀隔离（/cm/*）
- 不进入 BeukayClaw Hermes router（独立 cutmatrix-router）

可能的合并路径（P3 之后）：
- **Option A**：cutmatrix 撤掉，能力下沉到飞轮（cm_compose_task → 复用 video_assembly_task）
- **Option B**：保留 cutmatrix 作为独立模块，Agent C 内部调 /cm/compose/paragraph-align
