# Agent OS 前端改版设计（基于原版截图语言）

## 1. 背景
当前 Agent OS 已完成最小业务闭环：
- Agent Studio 已能完成定义、发布与跳转闭环观测
- Agent Registry / Skill Registry / Agent Identity / Observability 已接入真实后端接口
- 但页面视觉风格仍偏临时拼装，信息层级、组件复用与整体辨识度不足

本次改版仅针对以下 5 个页面：
1. `AgentStudio`
2. `AgentRegistryPage`
3. `SkillRegistryPage`
4. `AgentIdentityMgmt`
5. `AIExecutionTracker`

用户已明确要求：
- 只改这 5 个 Agent OS 页面，不改全站壳层
- 视觉样式以“原版前端截图”为准
- 优先目标是 **可读性 + 信息密度**
- 设计方向采用 **原版语言 + 数据页增强**

## 2. 目标

### 2.1 业务目标
让 Agent OS 五个页面从“接口已接通的功能页”升级为“可直接演示与持续扩展的企业级管理控制台”。

### 2.2 体验目标
- 统一成同一套 Agent OS 视觉语言
- 保留原版截图的浅色卡片风格
- 在高密度数据场景下仍保持良好的浏览效率
- 明确区分页面头部信息、指标区、筛选区、主体区、详情区

### 2.3 非目标
本次不做：
- 全站 Layout / 侧边栏 / 全局导航重构
- 后端 API 协议变更
- 页面业务逻辑重写
- 组件库大规模抽象或迁移
- 其他业务模块的视觉统一

## 3. 设计原则

### 3.1 原版视觉语言对齐
统一采用原版截图中的设计特征：
- 暖白 / 浅粉背景
- 轻粉描边
- 大圆角卡片
- 粉色胶囊筛选器
- 大数字指标卡
- 分组标题 + 内容模块化布局

### 3.2 上轻下重
每个页面统一采用以下结构：
- 顶部：标题、说明、操作按钮
- 中部：胶囊标签 / 筛选条 / 关键指标卡
- 下部：高密度主体内容（表格、列表、详情、表单、时间线）

### 3.3 展示感与管理感并存
视觉上保留原版“运营工作台”观感，但底层结构仍按真实管理后台组织，避免为了好看牺牲信息承载能力。

### 3.4 五页统一，不做五套皮肤
五个页面共用统一的：
- Hero 区结构
- 指标卡样式
- 筛选条样式
- 分组标题样式
- 内容容器样式
- 状态 badge 语义与色彩映射

## 4. 统一页面框架

### 4.1 Page Hero
每页头部包含：
- 页面标签（例如 `Agent OS / Studio`）
- 主标题
- 一段用途说明
- 右侧主操作按钮或刷新按钮

### 4.2 Metrics Row
头部下方统一采用 3~4 张大数字卡：
- 数字为主
- 标签为辅
- 同页仅保留最重要指标
- 不引入复杂图表

### 4.3 Filter Bar
筛选区采用原版截图同类的胶囊与轻边框输入框：
- 搜索框
- 状态筛选
- 分类筛选
- 视图切换（如有）

### 4.4 Section Card
主体内容统一放入浅色大卡片中，卡片内再承载：
- 表格
- 列表
- 表单
- 时间线
- 明细区

### 4.5 Status Badge
统一状态表现：
- `ACTIVE / SUCCESS / PUBLISHED`：粉主色系中的高亮成功态
- `RUNNING`：紫色系或蓝紫系
- `FAILED / SUSPENDED / ARCHIVED`：更深色或警示色，但仍保持与整体浅色体系兼容

## 5. 页面级设计

### 5.1 Agent Studio
**定位：** 定义、发布、校验一体化工作台

**结构：**
1. Hero：标题 + 定义到闭环说明 + 刷新按钮
2. 胶囊条：`Definition / Publish / Registry / Trace`
3. 指标卡：总定义、已发布、失败、最近发布
4. 主体区采用左右双栏：
   - 左栏：Definition 列表卡片
   - 右栏：Definition 编辑器
5. 编辑器下方保留：
   - Skill Preview
   - Last Publish 结果卡
6. 发布成功后继续保留跳转 Observability 的入口

**设计重点：**
- 左侧列表更像原版卡片矩阵中的“对象卡”
- 右侧编辑区保持真实表单能力
- 发布结果卡与闭环关系更明确

### 5.2 Agent Registry
**定位：** 运行时实例总表

**结构：**
1. Hero：标题 + Registry 运行说明 + 同步按钮
2. 指标卡：总实例、ACTIVE、SUSPENDED、已绑定定义
3. 筛选条：搜索、状态筛选、分类筛选
4. 主体区：高可读性表格
   - 保持横向信息完整
   - 表头减重
   - hover 行高亮
   - badge 统一风格
5. 可选轻详情区：保留行内说明，不增加重型弹窗

**设计重点：**
- 视觉上对齐原版浅卡片风
- 交互上仍保持“强管理页”的效率

### 5.3 Skill Registry
**定位：** 技能资产目录

**结构：**
1. Hero：标题 + 技能目录说明 + 刷新按钮
2. 指标卡：总技能、LOCAL、MCP、ACTIVE
3. 筛选条：搜索、来源筛选、分类信息
4. 主体区采用卡片矩阵
5. 卡片内展示：
   - 名称
   - `skillId`
   - 来源
   - schemaVersion
   - artifactPath 摘要
   - checksum 摘要

**设计重点：**
- 五页中最适合卡片矩阵表达的一页
- 既像资产库，又保留管理信息

### 5.4 Agent Identity
**定位：** 身份、权限、授权策略治理页

**结构：**
1. Hero：标题 + 身份治理说明 + 刷新按钮
2. 指标卡：总身份、ACTIVE、SUSPENDED、HYBRID
3. 主体区采用左右双栏：
   - 左栏：身份列表卡片
   - 右栏：身份编辑表单
4. 右侧表单分组：
   - 基本信息
   - 归属与类型
   - 授权策略
   - 公钥 / 标识
   - 生命周期状态

**设计重点：**
- 强化治理类页面的“可信、规整、专业”感
- 左右栏的信息层级要比现状更稳定

### 5.5 Observability
**定位：** 发布闭环观测台

**结构：**
1. Hero：标题 + 闭环验证说明 + 刷新按钮
2. 指标卡：Trace 总数、成功、运行中、平均耗时
3. 胶囊筛选：Definition / TraceStatus / PublishStatus
4. 主体区左右双栏：
   - 左侧：Trace Stream（高密度表格或流式列表）
   - 右侧：Recent Timeline + Publish Records
5. 底部保留最小闭环验证清单

**设计重点：**
- 保留原版看板式观感
- 同时保证追踪与排查效率
- 让该页成为 Agent Studio 发布后的“自然下一站” 

## 6. 视觉规范

### 6.1 色彩
- 背景：暖白与极浅粉
- 主要边框：浅粉描边
- 主强调：品牌粉
- 辅助强调：酒红 / 紫色
- 文本：深酒红或深灰红

### 6.2 圆角与边框
- 页面主容器：大圆角
- 指标卡与主体卡：大圆角
- 输入框与胶囊：全圆角或中大圆角
- 阴影轻微，仅辅助层次，不走厚重拟物风

### 6.3 字体层级
- 页面标题：大号、粗体、深色
- 指标数字：更大、更重
- 次级说明：轻量、偏灰粉
- 表格正文与卡片正文：强调可扫读性，避免过细字体

## 7. 实现策略

### 7.1 最小侵入式改造
仅改 Agent OS 五页及其必要的轻量样式，不动其他业务页面。

### 7.2 样式组织
优先在现有前端样式体系上增加 Agent OS 专属样式层：
- 页面级 class
- 共用卡片 / 指标 / 筛选条样式
- 避免全局覆盖引起其他页面回归风险

### 7.3 组件抽取范围
仅抽取低风险、复用明确的展示层结构，如：
- 轻量头部块
- 指标卡
- 胶囊筛选组
- Section 容器

不做大规模组件库重构。

### 7.4 接口与行为
保持当前已打通的 API 与交互流程不变：
- 继续使用现有 `agentApi.ts`
- 不修改后端契约
- 不改变已有发布 / 查询 / 更新逻辑

## 8. 测试与验收

### 8.1 视觉验收
- 5 个页面视觉风格统一
- 与用户给出的原版截图语言一致
- 明显优于当前临时页面状态

### 8.2 功能验收
- 现有增删改查与发布行为不回退
- Studio → Publish → Observability 仍然可用
- Registry / Skill / Identity / Trace 的真实接口展示正常

### 8.3 技术验收
- `npm run build` 通过
- 不引入新的控制台错误
- 不破坏其他路由

## 9. 分阶段实施建议
1. 先建立 Agent OS 统一样式基座
2. 优先改 `AgentStudio` 与 `AIExecutionTracker`
3. 再改 `AgentRegistryPage`、`SkillRegistryPage`、`AgentIdentityMgmt`
4. 统一微调 spacing、badge、筛选条与卡片边界
5. 最后执行 build 验证与整体巡检

## 10. 最终决策
本次改版采用：
- **视觉方向：** 用户提供的原版浅色卡片风
- **落地方式：** 原版语言 + 数据页增强
- **范围：** 仅 Agent OS 五页
- **优先级：** 可读性与信息密度优先于炫技视觉
